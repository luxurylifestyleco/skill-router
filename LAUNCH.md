# Launch kit

Skill Router by [@luxurylifestyleco](https://github.com/luxurylifestyleco) at [VEDAXI](https://vedaxi.com) has one memorable promise:

> Install skills. Forget their names. Ask naturally.

Target users are developers and power users whose agent-skill collections have become large enough that discovery and invocation are annoying.

## Proof before promotion

Before asking for stars, publish:

- the passing behavioral suite covering all eight action buckets and four purpose mappings;
- a 30-second terminal recording of local discovery;
- a public synthetic catalog with 25–100 skills;
- routing accuracy results on labeled requests;
- a clear disclosure that private catalogs never leave the machine.

Do not use the creator's private skill stack as content or a benchmark fixture.

## Five cost-efficient growth ideas

### 1. The forgotten-skill demo

- **Channel:** X, LinkedIn, Reddit, Hacker News, and agent-builder communities.
- **Core message:** “I installed dozens of agent skills and stopped remembering their names. This local router chooses them for me.”
- **Why it works:** It demonstrates a recognizable pain and the solution in one terminal recording.
- **Cost efficiency:** One recording can be reused across channels and embedded in the README.

### 2. The public 100-skill challenge

- **Channel:** GitHub repository, technical blog posts, and benchmark discussions.
- **Core message:** “Can a zero-model local router find the right skill in a 100-skill public catalog?”
- **Why it works:** Reproducible evidence is more credible and linkable than feature claims.
- **Cost efficiency:** Community members can contribute labeled cases and improve the dataset.

### 3. Adapter contribution loop

- **Channel:** Pull requests and partnerships with agent-tool maintainers.
- **Core message:** “Add your host in a small adapter; keep the routing contract unchanged.”
- **Why it works:** Every adapter gives another community a reason to link to and star the core repository.
- **Cost efficiency:** Maintainers contribute compatibility while the core remains provider neutral.

### 4. Pre-LLM routing field notes

- **Channel:** Repository discussions, a lightweight blog, and search-indexed technical articles.
- **Core message:** Explain action classification, purpose-bucket selection, skill privacy, routing confidence, failure modes, and eval design with real fixtures.
- **Why it works:** A focused body of useful material builds domain authority around a specific category.
- **Cost efficiency:** Each implementation lesson becomes documentation, an article, and a shareable diagram.

### 5. skills.sh release loop

- **Channel:** skills.sh, tagged GitHub releases, release posts, and README install snippets.
- **Core message:** “Add one skill that helps you use all the others.”
- **Why it works:** The distribution channel and the product problem are naturally aligned.
- **Cost efficiency:** Each release creates a new reason to post, update users, and request feedback.
